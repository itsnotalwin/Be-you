# Real-browser verification (BE YOU)

The existing `npm test` checks integrity and simulated application flows. `npm run test:browser` adds genuine Chromium (320px, 390px, 1280px) and WebKit (393px) navigation, image loading, responsive layout, mood geometry and persistence tests. It does **not** change the approved UI or artwork.

```sh
cd app
npm install
npx playwright install --with-deps chromium webkit
npm test
npm run test:browser
PLAYWRIGHT_CAPTURE=1 npm run test:browser
```

The browser suite opens 21 direct screen routes, then the two data-dependent journal states. It captures real rendered screenshots into ephemeral Playwright result folders when `PLAYWRIGHT_CAPTURE=1`. It independently tests all five mood selections within **one** reactive route, confirming each approved file loads and its natural proportions survive rendering. Browser tests use an isolated synthetic localStorage profile, with no user information.

GitHub Actions runs original tests first, then four real browser viewport projects, uploads reports/screenshots even on failures and blocks Pages deployment on failure. A post-deploy Chromium smoke checks the published commit marker and the live mood selector.

**Evidence boundary:** This is not yet a reviewed pixel-diff baseline for the 23 concepts; screenshots must be inspected/approved before adding snapshot comparisons. WebKit is a Safari-engine approximation, not a physical iPhone test. Offline installation, native safe-area behaviour, screen-reader accessibility and security/privacy audits remain separate gates. Real screenshots checked into `app/SCREENSHOT*.png` are historical until deliberately updated from real current captures; CI artifacts do not silently replace them.
## Pixel-level regression snapshots (2026-10-17)

`app/tests/visual.spec.mjs` adds actual pixel comparisons via Playwright `toHaveScreenshot`; baseline PNGs live in `app/tests/visual-baselines/` and use project-qualified filenames. The screenshot environment is frozen to UTC 2026-10-17 12:00, en-US, device pixel ratio 1, fixed viewports and reduced motion. It waits for artwork/fonts to load and suppresses cursors/animation. Its 0.1% max-different-pixel tolerance and color-difference threshold catch substantive layout, spacing, typography and image changes without pretending that every antialiased edge is reproducible across arbitrary machines.

The **390px Chromium canonical set** covers 21 direct routes + populated/view journal states + each of the five approved mood portraits in both top-of-page and scrolled-control states. Additional 320px Chromium, 1280px desktop Chromium and 393px WebKit sets protect key responsive views. Snapshots are platform-dependent; Linux GitHub Actions is the canonical comparison environment.

**Review process:** The initial snapshots must be generated by running `npm run test:browser -- --update-snapshots` against the real app on the separate `qa/visual-regression-baselines-20261017` review branch. A dedicated GitHub workflow performs this one-time capture and commits candidates to that branch, not `main`. Review actual images against approved concepts and check any unexpected cropping/layout before merging. On future intentional visual edits create a dedicated reviewed update PR; do not update snapshots as a quick fix for red tests. On failures inspect the expected/actual/diff PNG artifacts in GitHub Actions. Native device and accessibility QA remain separate.

Snapshot files are regression evidence, **not UI assets**; deployment staging excludes tests and browser reports. The signed-off mockups in `references/approved` retain their own status and must not be described as live screenshots.
